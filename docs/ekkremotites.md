# Εκκρεμότητες και ιδέες

Ό,τι αποφασιστεί να γίνει, ας πάει σε GitHub Issue (υπάρχουν έτοιμα templates). Όποιος τελειώνει κάτι, το σβήνει από εδώ.

## Αποφασισμένα
- [ ] Ειδοποιήσεις push (και πιθανή αφαίρεση των «Μηνυμάτων») — υπάρχει ήδη `profiles.push_token`
- [ ] Πραγματική πληρωμή με Viva (τώρα δοκιμαστική, 019)
- [ ] Τοποθεσία: «κοντά μου» στην αναζήτηση
- [ ] Πριν την κυκλοφορία: κείμενο απορρήτου και πραγματικό email επικοινωνίας (`lib/privacy.tsx`)

## Προτάσεις (δεν έχουν αποφασιστεί, 2026-11-20, από το Claude του Λεωνίδα)
- **Ξεχωριστή βάση για δοκιμές**: οι προεπισκοπήσεις των PR μιλάνε με την κανονική βάση. Ένα δεύτερο project Supabase (ή Supabase Branching) για τα PR θα προστάτευε τους αληθινούς λογαριασμούς.
- **Αυτόματο τρέξιμο των migrations** με GitHub Action (`supabase db push`) μετά το Merge, ώστε να μην ξεχνιούνται. Θέλει το access token ως secret στο repo.
- **Έλεγχος migrations σε κάθε PR**: Postgres στο CI που τρέχει `schema.sql` + όλα τα migrations με τη σειρά, για να πιάνονται λάθη SQL πριν το Merge.
- **Λίγα tests** (π.χ. `lib/client/search.ts`, `lib/store/key.ts`, υπολογισμοί πακέτων) με `node --test`, χωρίς βαριές βιβλιοθήκες.
- **Παρακολούθηση σφαλμάτων** (π.χ. Sentry) για να ξέρετε όταν κάτι σπάει σε κινητό πελάτη.
- **Releases με αριθμό έκδοσης** (tags `v1.x`) και APK στο Release αντί για artifact που λήγει σε 30 μέρες.
- **EAS Build** για Play Store / App Store όταν έρθει η ώρα (υπάρχει ήδη `eas.json`).
- **Καθάρισμα παλιών branches** που έχουν μπει ή εγκαταλειφθεί (`ui-redesign`, `home-top-variants`, `ui-preview-build`, `vathmologies` κ.λπ.).
- **Υπενθύμιση ραντεβού** (email ή push την προηγούμενη μέρα) — μειώνει τα «δεν ήρθε».
- **Προσβασιμότητα**: `accessibilityLabel` στα κουμπιά-εικονίδια (♥, ⓘ, ＋).
