# Συνεργασία: Στάθης και Λεωνίδας (και τα Claude τους)

Δύο άνθρωποι δουλεύουν στο repo, ο καθένας με το δικό του Claude:

| Ποιος | GitHub | Πώς δουλεύει |
|---|---|---|
| **Στάθης** (ιδιοκτήτης) | `stsak19` | Γράφει κατευθείαν στο `main`. Κάνει τα Merge. Έχει τη Supabase και τις ρυθμίσεις του repo. |
| **Λεωνίδας** (συνεργάτης) | `LeoTheGreat777` | Κάθε αλλαγή σε νέο branch από το τελευταίο `main` (`leonidas/<θέμα>`, ή το `claude/…` που δίνει το Claude Code), και ένα PR για να το δει ο Στάθης. Ποτέ κατευθείαν στο `main`. |

## Ποιος έκανε τι

Τα commits γράφονται συχνά ως «Claude» και από τους δύο, οπότε το όνομα του commit δεν αρκεί. Από 2026-11-20:

- Κάθε commit έχει στο τέλος του μηνύματος μια γραμμή **`Από: Στάθης`** ή **`Από: Λεωνίδας`**.
- Κάθε αλλαγή που φαίνεται (λειτουργία, βάση, εμφάνιση) γράφεται και στο [`CHANGELOG.md`](../CHANGELOG.md) με **[Στάθης]** ή **[Λεωνίδας]**.
- Το `scripts/allages.mjs` διαβάζει τη γραμμή `Από:` (και μέσα στα merge των PR). Για τα παλιότερα καταλαβαίνει μόνο του: merge από `leonidas/*` ή commit του `LeoTheGreat777` = Λεωνίδας, όλα τα άλλα στο `main` = Στάθης.

## Στην αρχή κάθε session (κανόνας για κάθε Claude)

Το `.claude/settings.json` τρέχει μόνο του το `node scripts/allages.mjs` όταν ανοίγει το Claude Code, και το αποτέλεσμα μπαίνει στο context. Αν δεν έτρεξε, τρέξε το εσύ (`npm run allages`).

1. Βρες για ποιον δουλεύεις (Στάθης ή Λεωνίδας).
2. Πες του **σε 3–6 γραμμές** τι έκανε ο άλλος από το τελευταίο «είδε μέχρι» (παρακάτω): τι άλλαξε για τον χρήστη, νέα migrations, κανόνες.
3. Για κάθε **ανοιχτό PR** του άλλου:
   - στον Στάθη: «Ο Λεωνίδας έχει ανοιχτό το PR #N (…). Θες να το δεις και να το κάνεις Merge ή όχι;» Με δείξε τι αλλάζει, αν έχει migration, και τον σύνδεσμο της προεπισκόπησης (`pr-preview/pr-N`).
   - στον Λεωνίδα: πες ποια PR του περιμένουν ακόμα τον Στάθη.
4. Αν κάποιο PR που μόλις μπήκε έχει migration, θύμισε ότι πρέπει να τρέξει στη Supabase (δες [`features/vasi.md`](features/vasi.md)).
5. Όταν ο άνθρωπός σου τα έχει δει, άλλαξε το «είδε μέχρι» του στο τελευταίο commit του `main` (ο Στάθης κατευθείαν στο `main`, ο Λεωνίδας μέσα στο επόμενο PR του).

## Σε κάθε αλλαγή

- Ενημέρωσε **στο ίδιο commit/PR** το σχετικό αρχείο στο `docs/features/`, το `CHANGELOG.md`, και το `README.md` αν άλλαξε κάτι που γράφει.
- Νέα λειτουργία χωρίς αρχείο; Φτιάξε `docs/features/<όνομα>.md` και βάλ' το στο index του `CLAUDE.md`.
- Νέα στήλη/πίνακας/συνάρτηση = νέο αρχείο στο `supabase/migrations/` με τον επόμενο ελεύθερο αριθμό. Πριν το φτιάξεις, κοίτα το `main` **και τα ανοιχτά PR** για να μη διαλέξετε τον ίδιο αριθμό (έχει ήδη γίνει με το 016 και το 019).
- Πριν το commit: `npm run typecheck`.

## Branches

- Λεωνίδας: `leonidas/<θέμα>` (π.χ. `leonidas/eidopoiiseis`) ή `claude/…` από session του Claude Code στο cloud. Μετά το Merge το branch σβήνεται (κουμπί «Delete branch» στο PR).
- Τα παλιά branches του Στάθη (`vathmologies`, `ui-redesign` κ.λπ.) δεν τα πειράζει κανείς εκτός από τον Στάθη.
- Το `gh-pages` το γράφουν μόνο τα workflows.

## Για να μη συγκρούονται τα δύο Claude

- Ένα PR = ένα θέμα. Μικρά PR μπαίνουν πιο γρήγορα και δεν συγκρούονται.
- Αν το PR μείνει πίσω από το `main`, κάνε `git merge origin/main` στο branch (όχι rebase/force push).
- Μην αλλάζεις αρχεία που ο άλλος δουλεύει εκείνη τη μέρα χωρίς λόγο. Αν πρέπει, γράψ' το στο PR.
- Ό,τι αποφασίστηκε με τον άνθρωπο (π.χ. «χωρίς demo») γράφεται στο `CLAUDE.md` ή στο αρχείο της λειτουργίας, για να το ξέρει και το άλλο Claude.
